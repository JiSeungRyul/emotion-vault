# Feature Specification: Emotion Capsule Journal

**Feature Branch**: `001-emotion-capsule`  
**Created**: 2025-11-27  
**Status**: Draft  
**Input**: User description: "사용자의 감정을 '텍스트 일기'가 아니라 '감정 캡슐' 형태로 저장하고, 나중에 그 감정을 다시 회상할 수 있는 웹 앱을 만든다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 감정 캡슐 기록 (Priority: P1)

사용자는 강도, 색상, 감정 타입, 짧은 문장, 메모를 입력해 감정 캡슐을 저장한다.

**Why this priority**: 캡슐 생성이 핵심 가치(감정 기록)이며 이후 회상·타임라인 기능의 기반이다.

**Independent Test**: 새 캡슐 생성 후 저장 완료 메시지와 DB에 정상 기록 여부를 확인한다.

**Acceptance Scenarios**:

1. **Given** 캡슐 입력 폼이 보일 때, **When** 필수 항목을 입력하고 저장하면, **Then** 성공 메시지와 함께 타임라인에 새 항목이 나타난다.
2. **Given** 강도 0/100 등 경계값 입력 시, **When** 저장하면, **Then** 유효성 오류 없이 값이 그대로 저장된다.

---

### User Story 2 - 타임라인 조회 (Priority: P2)

사용자는 저장된 감정 캡슐을 시간순으로 목록/타임라인에서 확인한다.

**Why this priority**: 과거 기록을 훑어보는 기본 회상 흐름이며 검색·필터의 기반이다.

**Independent Test**: 최소 3개의 서로 다른 날짜의 캡슐이 시간순으로 노출되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 여러 캡슐이 존재할 때, **When** 타임라인 페이지를 열면, **Then** 최신순으로 카드가 정렬되어 표시된다.
2. **Given** 타임라인에서 특정 캡슐을 클릭하면, **When** 상세 페이지로 이동하여, **Then** 원본 데이터(강도, 색상, 타입, 문장, 메모, 일시)가 보인다.

---

### User Story 3 - 감정 회상(리뷰) (Priority: P3)

사용자는 특정 캡슐을 열어 몰입형 배경과 함께 당시 감정을 다시 느끼고 내용을 확인한다.

**Why this priority**: 기록의 목적이 회상에 있으므로 정서적 재현과 맥락 제공이 중요하다.

**Independent Test**: 캡슐 상세 뷰에서 색상/강도 기반 배경, 텍스트, 메모가 모두 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 캡슐 상세 뷰에서, **When** 페이지가 로드되면, **Then** 강도·색상 기반 배경과 감정 타입/문장/메모/일시가 모두 보인다.
2. **Given** 데이터가 없거나 잘못된 캡슐 ID로 접근 시, **When** 로드하면, **Then** 404 또는 안내 메시지가 보인다.

---

### Edge Cases

- 강도 최소/최대(0, 100) 입력 시 저장·표시가 정상 동작해야 한다.
- 색상 코드 형식 오류 시 즉시 검증 에러를 보여준다.
- 중복 제출(더블 클릭) 시 단일 캡슐만 생성되어야 한다.
- 존재하지 않는 캡슐 ID 접근 시 404/안내 화면을 제공한다.
- 네트워크 오류 시 저장 재시도 안내와 로컬 상태 보존을 제공한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 사용자는 강도(0~100), 색상(hex), 감정 타입(사전 정의), 짧은 문장, 메모를 입력해 감정 캡슐을 생성할 수 있어야 한다.
- **FR-002**: 시스템은 필수 필드(강도, 색상, 타입, 짧은 문장)를 검증하고 오류를 UI에 명확히 표시해야 한다.
- **FR-003**: 저장된 캡슐은 타임라인에서 최신순으로 조회되고, 카드에는 색상/강도/타입/문장/일시가 표시되어야 한다.
- **FR-004**: 타임라인 항목 클릭 시 캡슐 상세 뷰로 이동하여 모든 필드(강도, 색상, 타입, 문장, 메모, 생성 시각)를 보여야 한다.
- **FR-005**: 성능 목표: API p95 <400ms(예상 부하), 페이지 TTI <3s(중급 기기)로 응답해야 한다.
- **FR-006**: 저장 실패(검증·네트워크·서버 오류) 시 친절한 에러 메시지와 재시도 옵션을 제공해야 한다.
- **FR-007**: 주요 이벤트(캡슐 생성 성공/실패, 상세 뷰 오류)에 대해 구조화된 로그를 남겨야 한다.
- **FR-008**: 데이터 일관성을 위해 중복 제출을 방지하거나 멱등 처리해야 한다.

### Key Entities

- **EmotionCapsule**: 강도(number 0~100), 색상(hex), 타입(enum), 짧은 문장(string), 메모(string, optional), 생성 시각(Date), ID.
- **User** *(선택/향후)*: 소유자 ID로 캡슐을 구분할 수 있어야 한다. 현 단계는 단일 사용자 가정, 다중 사용자 확장 시 인증 연계 필요.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 신규 사용자가 첫 캡슐을 생성·저장하는 데 2분 이내에 완료한다.
- **SC-002**: 타임라인 페이지 초기 로드 시 p95 TTI <3초, API p95 응답 <400ms를 유지한다.
- **SC-003**: 캡슐 생성 실패율(검증/서버 오류 포함)을 2% 이하로 유지한다.
- **SC-004**: 회상(상세 뷰) 시 필수 데이터 표시 누락률 0%를 달성한다.
